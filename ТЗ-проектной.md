1. Общие сведения

1.2. Тип проекта: индивидуальный, учебный (Яндекс.Лицей, модуль PyQt)

2. Цель и задачи
2.1. Цель: создать point&click игру «поиск предметов», в которой игрок в роли врача исследует слои памяти ветерана через прибор, чтобы восстановить причину его состояния. Стиль сцен меняется от светлого (детство) к мрачному (травма, палата).
2.2. Задачи:
     - реализовать игровую механику «поиска предметов» (клик по зонам, исчезновение предметов);
     - реализовать сюжетную рамку: главное меню, лорная вставка, досье образца, 4 уровня, записки между уровнями, меню паузы;
     - реализовать прогрессию уровней со сменой визуального стиля (Dreamcore -> Школа -> Война -> Палата);
     - обеспечить хранение данных в БД SQLite (таблица progress);
     - реализовать чтение текста записок из файла note.txt;
     - реализовать стандартные диалоги (QMessageBox при выходе);
     - собрать приложение в .exe.

3. Место, время, сюжет
3.1. Место и время: 2152 г., через 7 лет после Великой войны. ПИЦ №6, г. Моренвальд. Прибор для просмотра памяти изобретён в 2147 г. Масштаб и участники войны намеренно не раскрыты.
3.2. Роль игрока: доктор Келл Моррисон, сотрудник ПИЦ №6.
3.3. Задача игрока: исследовать Образец-2246А, восстановить причину его состояния по слоям памяти.
3.4. Основные сценарии:
     1) Доктор запускает приложение, попадает в главное меню.
     2) Открывает досье Образца-2246А и изучает его (часть строк засекречена).
     3) Запускает сеанс, читает лорную вставку, нажимает «Запустить сеанс».
     4) Игрок ищет предметы на сцене. Клик по предмету — находка (предмет исчезает, иконка в инвентаре меняет цвет).
     5) Когда все предметы найдены, открывается экран «Слой памяти» с запиской из note.txt.
     6) После прочтения записки начинается следующий уровень.
     7) После 4-го уровня игра возвращает в главное меню (конец игры).
     8) В любой момент игры можно нажать Esc, чтобы открыть меню паузы.

4. Функциональные требования
4.1. Роли пользователей: один игрок (доктор), без авторизации.
4.2. Основные функции:
     - главное меню (Начать / Досье / Выход);
     - экран досье образца (часть строк [ЗАСЕКРЕЧЕНО]);
     - лорная вставка с печатным текстом и прогресс-баром;
     - игровая сцена: фон + список предметов (сетка иконок);
     - обработка кликов по предметам (исчезновение, смена цвета в инвентаре);
     - экран «Слой памяти» с текстом из note.txt;
     - меню паузы (вызов по клавише Esc, кнопки «Продолжить» и «Выйти в меню»);
     - сохранение прогресса в БД SQLite;
     - стандартный диалог подтверждения выхода (QMessageBox).

5. Технические требования
5.1. Стек: Python 3.x, PyQt6, SQLite.
5.2. Управление зависимостями: requirements.txt.
5.3. Интерфейс:
     5.3.1. Несколько форм (6 экранов):
            - Menu (главное меню);
            - Dossier (досье образца);
            - Story (лорная вставка);
            - Notes (записки между уровнями);
            - Pause (меню паузы);
            - Lvl1-Lvl4 (игровые уровни).
     5.3.2. Использованы виджеты:
            - QLabel (тексты, фоны, иконки предметов);
            - QPushButton (кнопки меню, «Дальше», «Продолжить»);
            - QGridLayout (сетка инвентаря);
            - QVBoxLayout / QHBoxLayout (компоновка);
            - QStackedWidget (переключение экранов);
            - QProgressBar (прогресс-бар загрузки);
            - QFrame (лист бумаги, панели);
     5.3.3. Дополнительные виджеты:
            - QGraphicsColorizeEffect (эффект черного силуэта в инвентаре);
            - QGraphicsDropShadowEffect (тень для листа бумаги).
     5.3.4. Стандартные диалоги:
            - QMessageBox (подтверждение выхода из игры).
     5.3.5. Работа с изображениями:
            - фоны сцен (по одному на слой памяти);
            - иконки предметов (единый набор);
            - иконка приложения (.ico).

5.4. Работа с файлами (txt):
     - note.txt — тексты записок между уровнями (разделены тремя дефисами).
5.5. Работа с БД (SQLite):
     - таблица levels (id, status);
     - запись в БД: сохранение номера пройденного уровня (INSERT OR REPLACE);
     - чтение из БД: (в текущей версии только запись, но структура готова к чтению для функции «Продолжить»).
5.6. Сборка: приложение собирается в единый .exe (PyInstaller); папка assets и note.txt поставляются рядом с .exe.

6. Нефункциональные требования
6.1. Чистота кода: соблюдение PEP 8, осмысленные имена, отсутствие copy-paste, константы вынесены.
6.2. Проектирование: использование классов, наследование (BaseLevel -> Lvl1-Lvl4).
6.3. Объём кода: более 500 содержательных строк.
6.4. Работоспособность: все заявленные функции работают.
6.5. Читаемость сцен: предметы контрастнее фона на всех уровнях.
6.6. Атмосфера: сухой канцелярский язык, пометки [ЗАСЕКРЕЧЕНО], война без названия и масштаба; озвучка не используется — текст читается игроком.
